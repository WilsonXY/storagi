# Initial implementation agreement

One Node 22+ process, TypeScript; maintained `openid-client` for Google OIDC and `@tus/server` + `@tus/file-store` for resumable disk transfers. Plain TypeScript browser dashboard with `tus-js-client` and Vite. SQLite persistence preferred; no separate database service. Packages under `server/` and `web/`, each owns its package manifest/lockfile; coordinator owns root commands. Service agent may adjust internals, but records reasons. This is a single process service: do not run multiple writers.

Same-origin endpoints (all JSON errors `{error: string}`):

- GET `/api/session`: 200 `{authenticated: true, csrfToken: string, retentionDays: number, name: string|null, picture: string|null}` or 401. `name` and `picture` come from the owner's last Google login (`profile` scope) and are only sent to an owner session; `picture` is only ever a `https://lh3.googleusercontent.com/` URL.
- GET `/auth/login`, GET `/auth/callback`, POST `/auth/logout` (CSRF token).
- GET `/api/files?q=...`: `{files: [{id, name, size, uploadedAt, expiresAt}], usedBytes, reservedBytes, budgetBytes, retentionDays, textCount}`. ISO timestamps; completed Inbox files only, newest first. UUID suffix displayed in UI to distinguish repeated names.
- PUT `/api/settings`: JSON `{retentionDays, confirmDeletes?}` with `X-CSRF-Token`. `retentionDays` must be one of the positive whole-day values 1, 7, 14, 30, 60, 90; acknowledgement defaults to zero and must be a nonnegative safe integer. Returns 200 `{retentionDays}`. In one immediate transaction with one sampled time, count all live completed files (`uploadedAt IS NOT NULL AND expiresAt > now`) and live Text (`expiresAt > now`) whose proposed deadline is at or before now. File deadlines use `uploadedAt + duration`; Text uses `createdAt + duration`. `deleteCount` is the combined count. If the count exceeds acknowledgement, return 409 `{error, deleteCount}` and mutate nothing. Otherwise update both eligible item types from their original timestamps and persist the shared policy atomically. A growing count requires a fresh confirmation click; a smaller count may proceed. Cancel/Escape sends no acknowledgement. Owner devices use last-write-wins.
- GET `/api/files/:id/download`: protected attachment; byte ranges supported.
- DELETE `/api/files/:id`: deletes completed/partial file, CSRF header required.
- `/api/uploads` and `/api/uploads/:id`: standard tus creation/PATCH/HEAD/DELETE; cookie session on EVERY request. Known nonnegative Upload-Length required; reject deferred lengths and concatenation for simple atomic reservation. Metadata filename (base64 encoded by tus client). Creation Location same origin. Mutations require `X-CSRF-Token`; no cross-origin access.

Header `X-CSRF-Token` for every mutating API including tus POST/PATCH/DELETE. Login-only public shell is allowed; unauthenticated file endpoints never return file data. No production test-auth route, no default credentials or first-visitor owner enrollment.

200 GiB budget includes entire declared size of partial uploads reserved atomically before creation, completed content and filesystem free-space headroom. Store outside public web directory. Files begin retention at upload completion (including zero-byte and crash-recovered completions); Text begins at creation/send time. Both read the same committed SQLite policy, default 30 days. Authenticated session and file-list metadata expose that same committed value. Only an explicit settings save rewrites existing live deadlines; startup and rollback do not. Expired copies cannot be revived. Access stops at the saved expiry, physical cleanup is periodic, and active streams can retain quota; saving does not promise immediate space recovery. Partial uploads still expire after 24h inactivity. Cleanup at startup and periodically; safe against upload/delete/cleanup races. Restart recovery and error rollback must preserve quota correctness. Graceful termination; production HTTPS origin configuration, secure cookies, fixed callback URI; loopback HTTP for local tests only.

Text uses protected `GET /api/texts`, `POST /api/texts` and `DELETE /api/texts/:id` with the same owner/session/Origin/CSRF guards. Text list entries contain `{id, text, createdAt, expiresAt}` with ISO timestamps. Its authenticated weak ETag hashes ordered live IDs and expiry dates, so a deadline-only change invalidates conditional refresh even when membership stays the same. Exact Text content, the 64 KiB/item and 100-live-item limits, separate file quota, no link fetching and ordinary SQLite cleanup remain as described in [the server API](../server/README.md). Stored deadlines remain authoritative; startup does not silently re-date files or text.

Service uses `web/dist` for built dashboard. `createApp`/service factory supports isolated synthetic test state without exposing a production authentication bypass. Web tests can mock endpoints in test-only harness; label screenshots accordingly. UI includes Google login, picker/drop, queue with progress/pause/resume/cancel and reselect instructions after restart, Inbox search, storage/retention copy, download and confirmed deletion, useful error/status states, accessible responsive controls.
